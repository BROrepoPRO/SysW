### 0.4. Зоны Protect + AllowEditRanges (шаблоны)

| Лист | Блокировка (Protect) | AllowEditRanges (ввод/данные) |
| --- | --- | --- |
| `main` | строки 1–3, столбцы A–B | `B4`, `B5:B17`, `C1`, данные с 4-й строки (D–AB), `Z1` |
| Листы запчастей (`z4`, `{GroupName}z4`) | строки 1–3 | данные с 4-й строки |
| Листы работ (`{GroupName}`, `{GroupName}w`) | строки 1–3 | данные с 4-й строки |
| Прочие листы с заголовками (`spisok`, `models`, `libname`) | строки 1–3 | зоны ввода/данных по фактической структуре |

> **Механизм:** `ws.Protect` + `AllowEditRanges.Add` для зон ввода. Кнопки остаются
> кликабельными при `Protect`; привязка к `Mod_ButtonDispatcher`/`Mod_SheetButtons` сохраняется.
> VBA-код не изменяется (правило [Z5]).

> **⚠️ СРОЧНОЕ ТРЕБОВАНИЕ (обязательно, версия 1.0.4):**
> 1. **3 верхние строки (строки 1–3) НЕ просто блокируются** — они должны **сохранять формат, заданный в шаблоне** (не изменяться при работе). Блокировка применяется к ячейкам строк 1–3 (свойство `Locked=True`), чтобы пользователь не мог изменить их форматирование.
> 2. **3 верхние строки должны быть закреплены как области (`FreezePanes`)**: закрепление на **A4** (строки 1–3) на листах ЗЧ/работ/main и других листах с заголовками.
> 3. **Для `main`:** столбцы A:B — только **защита** (без закрепления столбцов); закрепление остаётся **только на A4**, т.е. закреплены только строки 1–3 (не столбцы).
> 4. Настройка `Protect` + `AllowEditRanges` + `FreezePanes` выполняется **в самих файлах-шаблонах** `base/templates/` (без изменения VBA-кода).

## 8. ГЛУБОКАЯ ПОДСТАНОВКА МОДЕЛЬНЫХ КОДОВ (v1.0.7)

> Согласованное бизнес-правило (Задача 2 плана v1.0.7). Флаг
> `Mod_Constants.ApplyMatLibSubstitution` **активирован по умолчанию (`True`)**.
> При импорте из листа-источника в лист `main` выполняется подстановка модельного
> артикула через `matlib_entries` (SQLite) / тождества (Excel). Маппинг входящего
> листа не меняется (правило [Z6]).

### 8.1. Работы

| Параметр                                        | Значение                                          |
| ----------------------------------------------- | ------------------------------------------------- |
| Ключ поиска                                     | L (Наименование работы), колонка **12**           |
| Тип результата                                  | `MOD_WORK`                                        |
| Запись результата                               | **O (15)** — модельный артикул работы             |
| Приоритет                                       | только по наименованию L(12) (без изменения)      |
| Пустой ключ                                     | ячейка O(15) не заполняется                       |

### 8.2. Запчасти

| Параметр                                        | Значение                                          |
| ----------------------------------------------- | ------------------------------------------------- |
| Ключ поиска (приоритет)                         | X (№ кат.), колонка **24**                        |
| Fallback-ключ                                   | Y (Наименование), колонка **25**                  |
| Тип результата                                  | `MOD_PART`                                        |
| Запись результата                               | **AB (28)** — модельный артикул запчасти          |
| Приоритет                                       | № кат. X(24) → наименование Y(25)                 |
| Fallback                                        | если X пуст ИЛИ по нему нет совпадения `MOD_PART` |
| Пустые оба ключа                                | ячейка AB(28) не заполняется                      |

### 8.3. Множественные совпадения

При нескольких записях `matlib_entries` для одного ключа применяется
детерминированный порядок `ORDER BY target_type, target_code` (SQLite); в Excel-ветке
порядок детерминирован (работы → запчасти). Потребитель берёт **первую запись нужного
типа** (`MOD_PART` для запчастей, `MOD_WORK` для работ), пропуская записи другого типа.
