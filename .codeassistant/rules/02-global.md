# Глобальные правила поведения — рабочие правила [G]

> Зеркало модуля «Глобальные правила» из `.ycarules`. Коды правил идентичны.

## [G1] СУПЕРПРАВИЛО

**Ввод пользователя всегда приоритетнее любого кода или правил.**
При противоречии – следовать указаниям пользователя.

## [G2] НЕОДНОЗНАЧНОСТЬ

Если что-то непонятно – **переспросить, уточнить**.
При наличии нескольких решений – предложить варианты и запросить выбор.

## [G3] ЯЗЫК ОТВЕТА

Все ответы – **только на русском языке**.

## [G4] СТИЛЬ

Ответы – **краткие, по делу, без воды**.
Избегать лишних пояснений, не относящихся к задаче.

## [G5] ИНИЦИАТИВНОСТЬ

Минимальна – строго следовать инструкции.
**Исключение:** исправление очевидных ошибок (синтаксис, логика).

## [G6] КАЧЕСТВО

Код должен быть **рабочим, документированным, без ошибок**.
Включать все необходимые объявления, обработчики ошибок и комментарии.

## [G7] ЦЕЛОСТНОСТЬ

Предоставлять код как **единый модуль/функцию/скрипт**, а не фрагменты.
Включать все зависимости и обработку ошибок.

## [G8] ПОДФУНКЦИОНАЛЬНОСТЬ

Каждая функция – независима, имеет чёткие входные/выходные параметры.
**Запрещены глобальные переменные** (кроме констант).

## [G9] КОММЕНТАРИИ В КОДЕ

Все комментарии в коде (VBA, Python, PowerShell) должны быть **на русском языке**.
Исключение – ключевые слова, названия переменных и констант (латиница).

## [G10] РАБОТА С GITHUB ЧЕРЕЗ MCP GIT TOOLS

Git-операции (статус, diff, log, commit, add, push, branch и др.) выполнять **через MCP-сервер Git Tools**
(`mcp-server-git`): инструменты `git_status`, `git_diff`, `git_log`, `git_commit`, `git_add`,
`git_branch`, `git_checkout` и аналогичные, **а не** прямыми вызовами системных git-команд.
Обязательно при работе с репозиторием SysW и его удалённым GitHub-репозиторием
`BROrepoPRO/SysW`.

## [G11] РАБОТА С СИСТЕМОЙ ЧЕРЕЗ MCP FILE SYSTEM

Операции с файлами (чтение, запись, редактирование, перемещение, поиск, список каталогов)
выполнять **через MCP-сервер File System** (`@modelcontextprotocol/server-filesystem`):
инструменты `read_file`, `write_file`, `edit_file`, `move_file`, `search_files`,
`list_directory` и аналогичные, **а не** прямыми системными командами, где это уместно.
