# Исключения и критические файлы — рабочие правила [E]

> Зеркало модуля «Исключения и критические файлы» из `.ycarules`. Коды правил идентичны.

> Поддерживаются **glob-паттерны**: `*`, `**`, `?`.

## Операции с файлами

### [E1] ИСКЛЮЧЕНИЕ (`Exclude`)

Ассистент **не читает, не анализирует, не изменяет** файлы/папки по паттернам.
*Пример:* `Exclude: "*.log", "_temp_export/*", "_backup/*", "*.tmp"`
*Пользовательские:* `Exclude: ""`

### [E2] ОБЯЗАТЕЛЬНОЕ ВХОЖДЕНИЕ (`Include`)

Ассистент **обязан учитывать** указанные файлы/папки при анализе контекста, даже если они не открыты.
*Пример:* `Include: "docs/*.md", "src/modules/Mod_Utils.bas"`
*Рекомендуемые:* `Include: "docs/DEVELOPER.md", "docs/ARCHITECTURE.md", "src/modules/Mod_Constants.bas"`

### [E3] КРИТИЧЕСКИЕ ФАЙЛЫ (защита)

Перечень (относительные пути):
- `work.xlsm`, `report.xlsx`, `README.md`, `docs/CHANGELOG.md`, `.ycarules`, `docs/ROADMAP.md`,
  `base/`, `base/models/` (всё содержимое);
- **рабочие правила:** `.codeassistant/rules/` (см. `[E5]`);
- **ключевые файлы системы (v1.1.0, Задача 6):** скрипты `scripts/*.py`, `scripts/*.ps1`,
  VBA-модули `src/modules/*.bas`, VBA-классы `src/classes/*.cls`, `src/sheets/*.cls`,
  конфигурация `.sourcecraft`, `.vscode/settings.json`.

**Правила защиты:**
- **Редактирование** – только по явной команде пользователя или после запроса и подтверждения.
- **Удаление** – категорически запрещено.
- **Порядок действий:**
  1. Подготовить план в `plans/` (см. `[U1]`).
  2. Указать целевой файл и планируемые правки.
  3. Отправить план пользователю, дождаться одобрения.
  4. Только после одобрения – вносить изменения.
- **Единый запрос на подзадачу:** если подзадача затрагивает несколько критических файлов из
  перечня – запрос на изменение формируется **один раз на все файлы подзадачи** (см. `[U4]`),
  все целевые файлы и правки указываются одним блоком для одной точки подтверждения.
- **Исключение:** временные файлы ассистента (после завершения удалить, см. `[S7]`).

## Контекст для ИИ

### [E4] ОБЯЗАТЕЛЬНЫЙ КОНТЕКСТ (`IncludeContext`)

При генерации/изменении кода – **обязательно учитывать** сигнатуры и логику указанных модулей/функций.
*Пример:* `IncludeContext: "Mod_Utils.*", "Mod_Logger.WriteLog", "Mod_Constants.*"`
*Пользовательские:* `IncludeContext: ""`

### [E5] ПРИОРИТЕТ ПРАВИЛ

При конфликте:
1. Явное `Include` переопределяет `Exclude`.
2. Критические файлы имеют наивысший приоритет защиты.
3. Более конкретный паттерн важнее общего.
4. При равной специфичности – приоритет у `Include`.
5. **Источник правил.** Рабочая область использует два источника: глобальный справочник
   `.ycarules` (разделы `[G]`–`[E]`) и рабочие правила `.codeassistant/rules/*.md`. Иерархия:
   а) прямое указание пользователя (`[G1]`);
   б) критические защиты `[Z*]` и критические файлы `[E3]`;
   в) рабочие правила `.codeassistant/rules/` (специфичны для рабочей области);
   г) общие положения `.ycarules`.
   Рабочие правила могут уточнять, но **НЕ отменяют** защиты `[Z*]` и `[E3]`.
