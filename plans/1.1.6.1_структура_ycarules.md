## 2. Вариант А — Зеркально-модульная структура `.ycarules`

### 2.1 Принцип

`.ycarules` становится **единым справочником правил**, разделённым на **8 тематических модулей**.
Каждый модуль имеет префикс-код (`[O]`, `[G]`, `[Z]`, `[K]`, `[U]`, `[S]`, `[T]`, `[E]`) и
**непосредственно соответствует** одному файлу в `.codeassistant/rules/` (зеркало).

Код правила (например `[G10]`, `[E3]`) — это **универсальный ключ**, который одинаков в `.ycarules`
и в `.codeassistant/rules/`. Это обеспечивает:
- однозначную ссылку из любого документа на правило;
- возможность частичного применения рабочего набора правил без потери смысла;
- автоматическую проверку синхронизации (скрипт `check_docs.py` может сверять коды).

### 2.2 Итоговая структура `.ycarules`

```
# Правила проекта SysW для SourceCraft Code Assistant
## Оглавление
## Легенда (карта: модуль -> код -> файл .codeassistant/rules/)
## 0. Принципы применения правил (обновлено)
   - два источника правил: .ycarules (справочник) + .codeassistant/rules/ (рабочие)
   - иерархия приоритета (см. [E5])
## 1. Модуль Роли           [O]  -> .codeassistant/rules/01-roles.md
   1.1 [O1] распределение задач
   1.2 Ролевые инструкции (5 блоков: Code, Ask, Architect, Debug, Orchestrator)
## 2. Модуль Глобальные правила [G] -> .codeassistant/rules/02-global.md
   [G1]..[G11]
## 3. Модуль Запреты         [Z]  -> .codeassistant/rules/03-restrictions.md
   [Z1]..[Z8]
## 4. Модуль Кодировка       [K]  -> .codeassistant/rules/04-encoding.md
   [K1]..[K3]
## 5. Модуль Изменения       [U]  -> .codeassistant/rules/05-changes.md
   [U1]..[U7]
## 6. Модуль Структура       [S]  -> .codeassistant/rules/06-structure.md
   [S1]..[S9]
## 7. Модуль Автодополнение  [T]  -> .codeassistant/rules/07-autocomplete.txt
   [T1]..[T4]
## 8. Модуль Исключения      [E]  -> .codeassistant/rules/08-exceptions.md
   [E1]..[E5]
## 9. Шаблон промта пользователя (инструкция для агента, учёт двух источников правил)
```

> **Примечание про нумерацию разделов.** Разделы получают сплошную нумерацию `1..8`,
> каждый — заголовок `<n>. Модуль <название> [<код>]`. Это устраняет путаницу старой схемы
> «1 Оркестратор и роли / 2 Глобальные … / … 9 Шаблон промта», где нумерация не совпадала
> с кодами групп.

### 2.3 Зеркальная структура `.codeassistant/rules/`

| Файл `.codeassistant/rules/` | Модуль `.ycarules` | Коды |
|------------------------------|--------------------|------|
| `01-roles.md`                | Роли              | `[O1]` + 5 ролевых блоков |
| `02-global.md`               | Глобальные правила| `[G1]`–`[G11]` |
| `03-restrictions.md`         | Запреты           | `[Z1]`–`[Z8]` |
| `04-encoding.md`             | Кодировка         | `[K1]`–`[K3]` |
| `05-changes.md`              | Изменения         | `[U1]`–`[U7]` |
| `06-structure.md`            | Структура         | `[S1]`–`[S9]` |
| `07-autocomplete.txt`        | Автодополнение    | `[T1]`–`[T4]` |
| `08-exceptions.md`           | Исключения        | `[E1]`–`[E5]` |

Каждый файл `.codeassistant/rules/` содержит **те же коды и формулировки**, что и соответствующий
модуль `.ycarules`. Различие только в контексте: `.ycarules` — полный справочник со всеми
пояснениями и примерами; `.codeassistant/rules/` — рабочие правила рабочей области.

> Приоритет применения: прямые указания пользователя → критические защиты `[Z*]`/`[E3]` →
> `.codeassistant/rules/` → общие положения `.ycarules` (см. `[E5]`, расширяется в `P15`).
