# Задание для Оркестратора: продолжение реализации ручного поиска работ (после сдвига структуры листа main)

Ты — Оркестратор. Мы возвращаемся к реализации **ручного поиска работ** в проекте SysW . **Важное изменение:** структура листа `main` была сдвинута на 2 строки вниз. Теперь:

- Шапка заказа начинается со строки **4** (ранее была строка 2).
- Таблицы работ (L:N) и материалов (X:AA) начинаются со строки **4** (ранее со строки 2).
- Первые две строки (1 и 2) зарезервированы под будущую логику и не должны заполняться.

Это изменение уже внесено в код и документацию (предполагаем, что задача выполнена). Твоя задача — продолжить разработку ручного подбора работ, **учитывая новое расположение данных**.

## Исходные данные (после сдвига)

- Кнопка **РУЧ РАБ** — заглушка `Btn_main_MANw()` в `Mod_MainButtons.bas`.
- Импортированные работы отображаются в диапазоне **L4:N** (начиная со строки 4).
- Группа модели определяется из ячейки **B14** (бывшая B12).
- Внешние файлы групп (`base/models/{Group}.xlsx`) — без изменений.
- Модуль `Mod_ModelDB` ещё не создан, потребуются базовые функции для доступа к файлам групп.

## Задача

Реализовать функционал ручного подбора работ: пользователь нажимает кнопку **РУЧ РАБ**, выбирает нужные работы из справочника группы, и они добавляются на лист `main` в определённое место (запросить у юзера). На этом этапе **не используется matlib** — только прямой выбор из справочника.

**Важно:** весь новый код должен работать с обновлённой нумерацией строк (данные начинаются со строки 4, а не 2). Пустые строки 1–2 остаются нетронутыми.

## Порядок работы

### 1. Ask (диалог с пользователем)

Начни опрос, учитывая новое расположение данных. Примеры вопросов:

- «После сдвига строк, куда именно на листе main вставлять выбранные работы? Раньше можно было использовать колонки O:P или отдельный блок. Теперь, с учётом того, что данные начинаются с 4-й строки, предложи конкретный диапазон (например, O4:P или новый блок ниже импортированных работ).»
- «Какой интерфейс для выбора работ удобнее: форма (UserForm) с фильтром, прямой переход на лист справочника группы, или InputBox для ввода кода/наименования работы?»
- «Какие поля работы должны отображаться при поиске? (Код, наименование, нормо-часы, цена)»
- «Нужна ли проверка на дублирование уже добавленных работ?»

Веди диалог до полного прояснения требований.

### 2. Architect (проектирование)

На основе ответов спроектируй:

- Функции для доступа к файлам групп: опирайся на спецификацию `Mod_ModelDB` из `docs/ARCHITECTURE_SQLITE.md`, раздел 3.3. Предложи создать минимальную версию модуля `Mod_ModelDB` с функциями `OpenModelGroupFile` и `GetWorks`, которые будут использоваться ручным подбором.
- Изменения в `Mod_MainButtons.bas` (замена заглушки `Btn_main_MANw()` реальным кодом).
- При необходимости создай новый модуль `Mod_Selection.bas` или `Mod_PickWork.bas` для логики подбора.
- Учти, что все операции с ячейками теперь должны использовать строки начиная с 4 (или с константы `MAIN_DATA_START_ROW`).
- Если нужен UI (UserForm или выбор на листе), опиши его структуру.

Представь план пользователю на утверждение (кратко, с указанием файлов и функций).

### 3. Code (реализация)

После утверждения:

- Создай или измени необходимые VBA-файлы (кодировка UTF-8).
- Замени заглушку `Btn_main_MANWRK()` рабочим кодом.
- Если создаётся `Mod_ModelDB` или другой модуль, реализуй его в соответствии с утверждённым планом.
- Синхронизируй модули с книгой (`python scripts/impVBA.py`) для тестирования.

### 4. Debug (проверка)

- Проверь, что ручной подбор работает корректно с реальными файлами групп (пользователь укажет путь).
- Убедись, что существующие функции (импорт, заполнение шапки, очистка) не сломаны и учитывают новый сдвиг строк.
- Проверь, что строки 1 и 2 остаются пустыми при любых операциях.

### 5. Завершение

- Обнови `CHANGELOG.md` (версия 0.11.0 с описанием ручного подбора работ и сдвига структуры).
- Закоммить изменения с сообщением `feat: реализация ручного поиска работ (адаптировано под сдвиг строк)`.
- Автопоиск (АВТОw) остаётся заглушкой.

## Важные правила

- Не вносить изменения без утверждения пользователем.
- Имена файлов и переменных — только латиница.
- Код должен быть модульным, с чёткими функциями.
- Использовать диалог (Ask) для уточнения на каждом этапе.
- Опираться на документацию (`DEVELOPER.md`, `ARCHITECTURE_SQLITE.md`, `ROADMAP.md`).
- Учитывать, что строки данных теперь начинаются с 4 (или использовать константу, если она была добавлена при сдвиге).
