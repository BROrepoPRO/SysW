## 1. Контекст и суть проблемы

Проект перенесён с диска `L:\PROject\SysW` на новый путь `f:/MiTyA/PROject/SysW`.
В конфигурационных файлах остались жёстко прописанные пути со старого диска `L:\...`,
из-за чего развёртывание на новом устройстве/по новому пути ломается.

**Ключевая причина:** захардкоженные абсолютные пути вместо относительных/динамических
(`${workspaceFolder}`).

3. После утверждения — перейти к Этапу 1.

### Этап 1 — Правки `.vscode/settings.json` (выполняет агент Code)

Точечные правки двумя SEARCH/REPLACE:

**1.1** Строка 17 — `terminal.integrated.cwd`:

+ "terminal.integrated.cwd": "${workspaceFolder}",

> Больше в `settings.json` ничего не меняем (профиль `SourceCraft`, кодировка,

### Этап 2 — Пересоздание `.venv` (выполняется ПОЛЬЗОВАТЕЛЕМ вручную в терминале)

> Почему не правим файлы вручную:
> `activate.bat` и `pyvenv.cfg` содержат битые пути и могут иметь внутренние
> несоответствия. Пересоздание гарантирует целостность venv на новом пути.
>
> ⚠️ Требует **ручного запуска в терминале** ПОСЛЕ исправления `cwd` в Этапе 1,
> чтобы терминал стартовал уже в правильной рабочей директории `f:/MiTyA/PROject/SysW`.

**2.1** Открыть в VS Code новый терминал (`Ctrl+Shift+`\`) — после правки Этапа 1 он должен
стартовать в корне проекта. Проверить cwd командой:
```bat
cd
```
Ожидается: `f:\MiTyA\PROject\SysW`.

**2.2** Выполнить пересоздание (одной строкой, правило `[S8]`):
```bat
del /S /Q .venv && python -m venv .venv && .venv\Scripts\activate && pip install -r requirements.txt
```

Пояснение по шагам:
- `del /S /Q .venv` — удалить старый битый venv (по согласованию, `[Z2]`).
- `python -m venv .venv` — создать чистый venv на текущем пути.
- `.venv\Scripts\activate` — активировать.
- `pip install -r requirements.txt` — установить зависимости.

> Если команда выполняется как единый блок — важен порядок операторов `&&`
> (последовательное выполнение). При желании можно разбить на отдельные команды.

**3.2 Активация `.venv` и python**

- Ожидается путь: `f:\MiTyA\PROject\SysW\.venv\Scripts\python.exe` (НЕ `L:\...`, НЕ `C:\Users\root\...`).
- В приглашении терминала должен присутствовать префикс `(.venv)`.

**3.3 Зависимости установлены**
```bat

```
- Присутствуют зависимости из `requirements.txt`.

**3.4 VBA открывает `work.xlsm`**
- В VS Code выполнить действие расширения VBA (например, «VBA: Open Excel Workbook»).
- Должен открыться файл по пути `f:/MiTyA/PROject/SysW/work.xlsm`

**3.5 Контроль отсутствия старых путей**

- Вывод должен быть пустым (совпадений нет).

## 6. Риски и примечания

- **Пересоздание `.venv`** удаляет старые установленные пакеты — необходимо повторно
  `pip install -r requirements.txt`. Файл `requirements.txt` должен существовать в корне.
- Если `requirements.txt` отсутствует или путь к нему отличается — уточнить у пользователя.
- Косметические правки (`Mod_ModelDB.bas:18`, README/docs) выполняются только по отдельному
  запросу и согласованию.
- Правки `settings.json` НЕ затрагивают критические файлы из `[E3]` (`.vscode/` в списке нет),
  но всё равно требуют согласования по `[U1]`/шаблону промта.
