## 5. Организация тестовых данных ([Z6])

### 5.1. Принцип
Согласно [Z6], тестовые данные допускаются **только** если нельзя использовать рабочие данные. Приоритет:
1. **Рабочие данные** — для `GetWorkIdentities`, `GetPartIdentities`, `GetWorks` (файл `base/models/UAZ.xlsm`), `FillHeaderFromOrder`, `FindOrder` (листы `spisok`/`models` в `work.xlsm`).
2. **Временные тестовые данные** — только для функций, где рабочие данные не подходят (например, `ImportDataToMain` с контролируемым листом-источником).

### 5.2. Конкретные решения
- **TC-22..TC-24 (ModelDB):** использовать существующий файл группы `UAZ` (`base/models/UAZ.xlsm`). Проверять, что коллекция непустая и элементы имеют корректные поля.
- **TC-25..TC-28 (OrderHeader):** использовать рабочие листы `spisok`/`models` в `work.xlsm`. Для существующего заказа — взять реальный номер из листа `spisok` (первую непустую строку). Для несуществующего — заведомо несуществующий номер (например, `999999`).
- **TC-29 (ImportDataToMain):** создать **временный лист-источник** в `work.xlsm` с таблицами "Выполненные работы" и "Расходная накладная" (структура по комментариям в `Mod_Import.bas`), вызвать `ImportDataToMain`, проверить перенос в L:N и X:AA, затем **удалить временный лист** ([S3]).
- **TC-30 (ImportSheet):** вызвать с несуществующим ГРЗ (например, `"НЕСУЩЕСТВУЮЩИЙ"`), проверить выход без ошибки при подавленном MsgBox.
- **TC-45 (SearchSheetByGRZ):** вызвать с несуществующим ГРЗ, проверить возврат `Nothing`.
- **TC-46 (AddWorkEntry):** вызвать `AddWorkEntry`, проверить, что запись `work.xlsm` присутствует в libname (идемпотентность — повторный вызов не дублирует).

### 5.3. Очистка
Все временные листы/данные удаляются после тестов ([S3]). Тесты должны восстанавливать исходное состояние листов (сохранение/восстановление значений ячеек, как в существующих TC-14, TC-36).

## 8. Процедура тестирования (run_tests.py)

### 8.1. Запуск
```bash
python scripts/run_tests.py
```
- Открывает `work.xlsm` через COM, устанавливает `B4=3`, запускает `RunAllTests`.
- Читает результаты из ячейки `Z1` листа `main`.
- Возвращает exit code: `0` — все PASS, `1` — есть FAIL.
- Результаты сохраняются в `logs/test_results.log`.

### 8.2. Критерии приёмки
- `Total` = ожидаемое количество тестов (40 существующих + новые).
- `Failed` = 0.
- `Skipped` = 4 (TC-41..TC-44, без увеличения).
- exit code = 0.

### 8.3. При неудаче
- Проанализировать `logs/test_results.log` и Immediate Window.
- Исправить **только тестовый модуль** (не бизнес-логику).
- Повторить цикл импорт → тест → экспорт.
