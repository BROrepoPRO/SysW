## 2. Механизм защиты листов (предлагаемый подход)

### 2.1 Постановка

Требуется защитить от изменения **форматирования**:
- **3 верхние строки** (2 под кнопки + заголовки) на: листе `main`, всех листах с запчастями, всех листах с работами и прочих листах с заголовками;
- на листе `main` **дополнительно первые 2 столбца** (A, B).

**Важно:** защита касается именно **форматирования** (шрифт, заливка, ширина, скрытие строк/столбцов), при этом пользователь должен иметь возможность **вводить данные** в ячейки ввода (например, `B4`, `C1` на листах UAZ) и редактировать таблицы данных (с 4-й строки).

### 2.2 Выбор механизма (варианты на согласование)

| Вариант | Описание | Плюсы | Минусы |
|---------|----------|-------|--------|
| **A. Защита листа Excel через `Protect` с разблокированными зонами ввода** (рекомендуется) | Лист защищается (`ws.Protect`), ячейки форматирования в верхних 3 строках блокируются (`Locked=True`), ячейки ввода/данных разблокируются (`Locked=False`); защита **без пароля** или с паролем | Нативно для Excel; блокирует форматирование; данные редактируемы | Нужно аккуратно выставить `Locked` на всех ячейках; скрытие/добавление строк ограничивается |
| **B. Защита форматирования через `EnableSelection` + `AllowFormattingCells`/`AllowFormattingRows`** | Уточнённые флаги `Protect` (`AllowFormattingCells`, `AllowFormattingRows`, `AllowFormattingColumns`) | Точечно управляет только форматированием | Сложнее настроить, зависит от версии Excel |
| **C. VBA-процедура `ProtectAllSheets`/`UnprotectAllSheets`** | Единая процедура в `Mod_SheetOps` или новом модуле, применяющая защиту ко всем листам при открытии/активации | Централизованно, воспроизводимо при интеграции шаблонов | Требует изменения кода (а задание требует «без изменения логики» — защита применяется на этапе формирования шаблонов) |
| **D. Настройка защиты на этапе создания шаблонов (разово)** | Защита настраивается в самих файлах-шаблонах вручную/скриптом при их создании, без VBA-логики в рантайме | Не требует изменения кода системы | Защита «запечатана» в файле; при пересоздании из исходника защита теряется |

**Рекомендация:** сочетание **A + D**. Защита настраивается **в шаблонах** на этапе их создания (задача 0), т.к. «без изменения логики кода». Это соответствует требованию защитить форматирование в шаблонах. При необходимости централизованная VBA-процедура (вариант C) — на отдельное согласование, так как вносит изменение в код.

> **⚠️ СРОЧНОЕ ТРЕБОВАНИЕ (обязательно, версия 1.0.4):**
> 1. **3 верхние строки (строки 1–3) НЕ просто блокируются** — они должны **сохранять формат, заданный в шаблоне** (не изменяться при работе). Блокировка применяется к ячейкам строк 1–3 (`Locked=True`), чтобы пользователь не мог изменить их форматирование.
> 2. **3 верхние строки должны быть закреплены как области (`FreezePanes`)**: закрепление на **A4** (строки 1–3) на листах ЗЧ/работ/main и других листах с заголовками.
> 3. **Для `main`:** столбцы A:B — только **защита** (без закрепления столбцов); закрепление остаётся **только на A4**, т.е. закреплены только строки 1–3 (не столбцы).
> 4. Настройка `Protect` + `AllowEditRanges` + `FreezePanes` выполняется **в самих файлах-шаблонах** `base/templates/` (без изменения VBA-кода).

> **Вопрос на согласование** — см. раздел 8, вопрос 3.

## 6. Этапы реализации (для режима Code)

> Порядок соответствует [U1]: сначала план и согласование, затем исполнение, затем перенос плана в `plans/_archive/`.

### Этап 0 — Создание шаблонов (СОВМЕСТНО С ПОЛЬЗОВАТЕЛЕМ)
1. Согласовать источники каждого шаблона (особенно `model.xlsm`/`model0.xlsm`).
2. Создать `base/templates/`.
3. Создать 5 шаблонов по таблице источников (копирование, удаление кода для `*0`).
4. Настроить форматирование верхних строк (строки 1–2 кнопки, строка 3 заголовки).
5. Создать шаблоны кнопок и формат кнопок.
6. Применить защиту форматирования 3 верхних строк (+2 столбца для main).

### Этап 1 — Интеграция шаблонов
1. Проверить наличие/целостность 5 шаблонов в `base/templates/`.
2. Обновить документацию (связи, назначение, процедура пересоздания).
3. НЕ изменять логику кода.

### Этап 2 — Защита листов
1. Определить точный перечень листов в каждом шаблоне.
2. Применить защиту форматирования 3 верхних строк (+2 столбца main) по выбранному механизму (раздел 2).
3. Проверить, что зоны ввода данных остаются доступны.

### Этап 3 — Версия и CHANGELOG
1. `python scripts/update_version.py 1.0.4`.
2. Дополнить `CHANGELOG.md` разделом v1.0.4 (шаблоны, защита, синхронизация).

### Этап 4 — Синхронизация коммитов и релиз
1. Коммиты в `dev` по областям (Conventional Commits) через MCP Git Tools.
2. PR `dev` → `main`.
3. Синхронизировать версию коммитов с v1.0.4.

### Этап 5 — Проверка системы
1. `python scripts/run_tests.py` — убедиться, что тесты проходят (защита листов не должна ломать тесты).
2. Проверить защиту листов вручную (форматирование недоступно, ввод данных доступен).
3. Проверить целостность шаблонов.

### Этап 6 — Проверка чистоты проекта ([S7])
- Удалить `__pycache__/`, `*.pyc`, временные `_temp_export/`, `_temp_import/`, случайные `*.tmp`, `~$*`, `*.sync-conflict-*`.
- Проанализировать `_backup/` (см. раздел 8, вопрос 6).
- `git status` не должен показывать мусор.

## 7. Риски

| Риск | Митигация |
|------|-----------|
| Шаблоны созданы неверно (не те источники) | Явное согласование источников до создания (задача 0) |
| Защита листов заблокирует ввод данных пользователем | Разблокировать зоны ввода/данных (`Locked=False`) при применении защиты; проверка в Этапе 5 |
| Защита листов сломает автоматические тесты (`run_tests.py` пишет в `B4`, `Z1`) | Проверить, что ячейки `B4`, `Z1` разблокированы; при необходимости тест требует адаптации (согласовать) |
| Изменение логики кода вопреки требованию | Интеграция шаблонов и защита выполняются только на уровне файлов/документации, без правок `.bas`/`.cls` |
| Пропуск версии v1.0.3 создаёт рассинхрон с историей коммитов | Согласовать вариант синхронизации (раздел 8, вопрос 2) |
| Правка критических файлов (`work.xlsm`, `report.xlsx`, `CHANGELOG.md`, `base/`) | Правка только по явной команде ([E3]) |

## 8. Вопросы, требующие решения пользователя

1. **Источники шаблонов `model.xlsm` / `model0.xlsm`.** Какой из файлов `base/models/*.xlsm` (4x4, 2170, 2180, 2190, GAZ, UAZ) брать за основу шаблона модельного файла? Или `model.xlsm`/`model0.xlsm` должны быть универсальной пустой структурой (листы `z4`, `{Group}z4`, `{Group}`, `{Group}w`)?

2. **Синхронизация версий коммитов.** Фиксировать ли пропущенную v1.0.3 (создать раздел CHANGELOG, обновить версию, сделать коммит) перед v1.0.4, или сразу перейти на v1.0.4 единым релизом?

3. **Механизм защиты листов.** Подтверждаете ли рекомендуемый вариант «A + D» (защита настраивается в шаблонах через `Protect` с разблокированными зонами ввода)? Нужна ли централизованная VBA-процедура (`ProtectAllSheets`) — она вносит изменение в код, поэтому требует отдельного одобрения.

4. **Процедура «последнего обновления кодовой базы» в шаблонах.** Когда шаблон `work.xlsm`/`model.xlsm` должен содержать «последнее обновление кодовой базы» и как это определяется? Достаточно ли однократного импорта `src/` в шаблон при его создании?

5. **Объём документации.** Достаточно ли секций в `docs/DEVELOPER.md` и `docs/ARCHITECTURE.md`, или нужен отдельный `docs/templates.md` со справочником форматирования верхних строк, шаблонов кнопок и их формата?

6. **Каталог `_backup/`.** Папка `_backup/` содержит множество старых файлов (`work_before_clean_rebuild.xlsm`, `work_after_reimport.xlsm`, `UAZ_backup_before_remove_work26.xlsm` и др.). Это намеренное хранилище (оставить) или мусор (удалить/перенести)? Папка `workOt/` аналогично — уточнить назначение.

7. **Каталог `base/temples/`.** Пустая папка `base/temples/` (опечатка `templates`?) — оставить, удалить или использовать как источник? Рекомендация: не использовать, т.к. целевой каталог — `base/templates/`.

8. **Формат кнопок.** Какой единый стиль кнопок задать в шаблонах (размер, цвет, шрифт, подписи)? Будут ли кнопки привязаны к существующим обработчикам `Mod_ButtonDispatcher` / `Mod_SheetButtons`?
